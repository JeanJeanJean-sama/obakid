# 作業メモ　v0.3.0：素材を差し替えられる仕組みへの作り替え

## 目的

v0.2.0 の遊びはそのままに、中身の作りを変えます。
画像・音・会話・キャラやマップのデータをプログラムから切り離し、「決まった名前のファイルを置けば、プログラムを触らずに見た目や文章が変わる」状態にします。
これは、このあとのグラフィック強化・BGM と効果音・ムービーイベントの土台になる作業です。

**遊んだときの見た目と内容は、v0.2.0 とほぼ同じで構いません。** 新しい遊びは追加しません。

## 作業の範囲

### やること

1. `v0.2/` をコピーして `v0.3/` を作り、そこで作業する（`v0.2/` は変更しない）
2. プログラムを役割ごとに複数のファイルに分ける
3. データを別ファイルに分ける
4. 画像の読み込みの仕組みを作る（画像が無ければ仮の図形で代用する）
5. 音を鳴らす仕組みを作る（音のファイルが無ければ何もしない）
6. イベントシーンの仕組みの「受け皿」だけ作る（中身は次以降の版）
7. パズルの検証プログラムを、データファイルのマップを読んで検証できる形で用意する
8. トップページ・CHANGELOG・README・DESIGN.md を更新する

### やらないこと

- 新しいキャラクター、マップ、道具、遊びの追加
- 本番用のグラフィックや音の制作（作者が別途用意する）
- パズルの配置やルールの変更（変更が必要だと思ったら相談すること）

## 目標のフォルダ構成（案）

細かい分け方は、作業前に作業者へ説明して確認を取ってください。

```
v0.3/
  index.html            ゲームの入り口（ほぼ読み込むだけ）
  js/                   プログラム（役割ごとに分ける）
    main.js             ゲームの設定と起動
    scenes/             場面ごとの処理（起動・読み込み、町と広場、図鑑など）
    systems/            共通の仕組み（会話、マス目移動と滑り、音、イベントシーン）
  data/                 プログラムを触らずに書き換えられるデータ
    assets.json         画像と音のファイル一覧（名前、場所、1コマの大きさなど）
    characters.json     キャラクターの名前と、使う画像の名前
    dialog.json         すべてのセリフ・説明文
    obakid.json         図鑑の内容
    maps/plaza.json     マップの配置（今の MAP の文字の並び）
  assets/
    images/             画像（作者が描いたドット絵を入れる）
    audio/              BGM と効果音
```

## 各部分の要件

### データの切り離し

- いまプログラムに直接書かれているセリフ、キャラ名、図鑑の文章、マップは、すべて `data/` のファイルに移す
- 主人公、ハナさん、タケル、ペロッパの名前は `characters.json` で変えられるようにする
- セリフは「誰が・どの場面で」話すものかがわかる名前で整理する（例：ハナさんの、モップ入手前のセリフ）
- `data/` のファイルの書き方を、作業者向けに README か `docs/` に短く説明する

### 画像の読み込み

- `assets.json` に書かれた画像を読み込む
- ファイルが無い、または読み込めなかった画像は、v0.2.0 と同じ仮の図形を自動で作って代わりに使う
  - こうすることで、作者が描けた絵から1枚ずつ差し替えていける
- キャラクターは、将来アニメーション（歩き、向き）を入れられる作りにしておく
  - 1コマの大きさや並べ方は `assets.json` で指定できるようにする
  - 仮の値として、タイルとキャラの1コマは 32×32 ピクセルとする。本番の大きさは後で作者と相談して決める
- どの画像を、どんな名前・大きさで用意すればよいかの一覧を `docs/` に作る（作者がドット絵を描くときの注文書になる）

### 音

- BGM と効果音を鳴らす共通の仕組みを作る
- ファイルが無い音は、エラーにせず鳴らさないだけにする
- 鳴らす場面のきっかけだけは先に入れておく（例：拭く、滑る、ぶつかる、水路に落ちる、網を振る、捕まえた、会話の文字送り、広場のBGM、勝負のBGM）
- 必要な音の一覧を、画像と同じように `docs/` にまとめる
- ブラウザは、遊ぶ人が一度クリックやキー入力をするまで音を鳴らせない決まりがあるので、それに対応する

### イベントシーンの受け皿

- 「キャラを指定のマスまで歩かせる」「セリフを表示する」「待つ」「画面を揺らす」などの命令を、データに書いた順番に実行する仕組みの土台を作る
- v0.3.0 では、ペロッパ登場の場面など、既存の会話の一部をこの仕組みで動かせば十分
- 台本の書き方の例を `docs/` に短く残す

### パズルの検証

- `data/maps/plaza.json` を読み込み、ゲームと同じルールで総当たり検証するプログラムを用意する
- 以下の3点を確認して結果を報告する
  - モップ4回で解ける
  - モップ3回では解けない
  - 木箱が無いと（木箱の位置をワックスにすると）、モップ4回では解けない
- 検証プログラムの動かし方を README に書く

## 完成の条件

- `v0.3/` が、v0.2.0 と同じように最初から最後まで遊べる（会話 → モップ入手 → パズル → ペロッパとの勝負 → 図鑑）
- パズルの検証で、上の3点が確認できている
- `assets/images/` に正しい名前の画像を1枚置くと、その見た目だけが変わる（試しに1枚作って確認し、確認後は元に戻す）
- `dialog.json` のセリフを1つ書き換えると、ゲーム内のセリフが変わる
- `v0.1/`、`v0.2/` は変更されていない
- トップページの最新版が v0.3.0 になり、v0.2.0 は過去の版に移っている
- CHANGELOG.md、README.md、DESIGN.md が更新されている
- コミットして `v0.3.0` のタグを付けている（GitHub への push は作業者の許可を取ってから）
